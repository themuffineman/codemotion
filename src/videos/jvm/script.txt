Here's how the JVM actually runs your code. You write a dot java file. Something happens behind the scenes, and your CPU ends up running machine code. Let's open App dot java. The main method adds twenty one plus twenty one, and then it prints the total. When you compile it, javac turns this into bytecode. Every class file the JVM loads, along with JARs and modules, carries this bytecode plus metadata. And that same bytecode runs on macOS, Linux, and Windows, because each platform ships its own JVM. But first, the class has to be found. The application class loader asks the platform loader, which asks the bootstrap loader. Delegation always goes up first. So what does all of this cost at startup? Class loading, verification, and JIT warm up add up to roughly two hundred milliseconds.
